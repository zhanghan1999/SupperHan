# 三层分离边界

本仓库遵循 L1 / L2 / L3 三层分离。**任何内容归层错误都会污染跨项目命中率**，请严格按下方判据分类。

## 三层定义

| 层 | 存放 | 格式 | 校验 | 出错后果 |
|----|------|------|------|---------|
| **L1 通用行为层** | 本仓库 `agents/` `commands/` `skills/` 及 `.qoder/rules/` | YAML frontmatter + Markdown | 无（内容即真相） | 逻辑坏 → 工具废 |
| **L2 项目契约层** | 私有根 `projects/<code>.yaml`（注册表；迁移期兼容单文件 `project.yaml`）+ `menus/<code>.yaml` + `drivers/` | 结构化 YAML | JSON Schema 校验 | 值错 → agent 决策错（数据事故风险） |
| **L3 个人习惯层** | 私有根 `prefs.md` | 自由 Markdown | 无 | 只是体验差 |

## 判据（任一命中即定层）

### 归 L2 的条件

1. **换项目时会改动** 的任何字面量（路径、库名、host、端口、分支名、模块名、包名、驱动脚本路径）
2. 被 agent 用 `if/==/in` **读取判断**的值（例如"当前目标库是否为测试库"的门禁字段）
3. 编译/测试/打包命令中会因项目而变的部分
4. 数据源接口路径、鉴权方式、健康检查地址
5. 取数走哪条通道（`script` / `mcp`）、允许的降级方式、MCP source 白名单与项目 adapter 路径 —— 均为“换项目就变 + 被脚本机械读取”的值，写进 L1 即红线 R3 的“把 L2 值塞进 L1”

### 归 L3 的条件

1. **换人时会改动** 的表现型偏好（输出详略、日志粒度、是否强制二次确认）
2. 个人笔记、踩过的坑、常用快捷路径
3. 不影响 agent 分支判断的软性提示

### 归 L1 的条件

1. 换项目、换人都不动的**角色定义、工作流、算法、协议**
2. **分批算法**（30KB 上限、按 Controller/Service 分片）
3. **CURRENT 原子切换**协议、copy-on-write 语义
4. **派发协议**：主 agent 派 subagent 的输入格式、输出格式、失败降级策略
5. **完成判定**：修复完成的必要条件清单
6. 跨项目通用的红线：禁止跳过 DB 门禁、禁止改生产配置、禁止 prelearn-writer / driver-author 之外使用 external_directory

## 灰色地带裁决规则

- 一段内容既像 L1 又像 L2 → **归 L2**（宁可值错不可逻辑错）
- 一段内容既像 L2 又像 L3 → **看是否被机械读取**：`if` 判断读 → L2；只是给模型参考 → L3
- 一个字段被两个不同 agent 以不同意图使用 → 拆成两个字段，各归其层

## L1 里的引用形式

L1 文件里凡是要引用 L2 具体值，**必须**用双花括号占位符：

- `PROJECT.<dot.path>` 表示从当前注册条目（`projects/<code>.yaml`）里查
- `TOOL_ROOT` / `PRIVATE_ROOT` / `DRIVERS_ROOT` / `CONTEXT_ROOT` 表示根路径
- `SYNC_TIMESTAMP` 表示同步时刻

sync 阶段完成替换；替换后仍残留双花括号字面量的字符串 → **阻断报错**，不降级。

通道选型字段（kind / fallback / mcp 段）**不在 L1 prompt 里引用**：它们是注册期探测的结论，由解析器在运行期读出后交给 `data-fetch` 的 resolve 段机械选定。在 L1 里引用它 = 把某一次的探测结论冻结进产物，重跑探测也改不动。L1 里描述这类字段时用自然语言（“目标槽位已配置的取数通道”），不写占位符。
